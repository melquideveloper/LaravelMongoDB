Ótima pergunta! 👍

Por padrão, o MongoDB diferencia letras maiúsculas/minúsculas e acentos quando você usa o operador like com Laravel/Eloquent.

Então isso aqui:

php

não vai encontrar nomes como "João da Silva", porque:

  • “J” maiúsculo é diferente de “j” minúsculo (em comparação binária)

✅ Como tornar a busca insensível a maiúsculas/minúsculas e acentos?

✅ Solução com regex do MongoDB

Você pode usar o operador $regex com a opção i (de insensitive).

🔧 Atualize a busca por nome assim:

php
if ($request->filled('nome')) {
    $query->whereRaw([
        'nome' => [
            '$regex' => $request->nome,
            '$options' => 'i'
        ]
    ]);
}

🧠 Mas... e acentos?

  • O modificador i ignora maiúsculas/minúsculas, mas não ignora acentos.

  • Para isso, você teria que normalizar os dados ou o termo de busca removendo acentos.

use Illuminate\Support\Str;

if ($request->filled('nome')) {

        'nome' => [
            '$regex' => $nomeNormalizado,
            '$options' => 'i'

    ]);

📝 Mas atenção:

  • Isso só funciona bem se os nomes salvos no banco também estiverem sem acento ou normalizados.

✅ Etapa 2: Criar método atualizar() no controller

php
use Illuminate\Support\Facades\Validator;

public function atualizar(Request $request, $id)
{
    $usuario = Usuario::find($id);

    if (!$usuario) {
        return response()->json(['erro' => 'Usuário não encontrado'], 404);
    }

    // Validação rápida (pode ser expandida com FormRequest)
    $validator = Validator::make($request->all(), [
        'nome' => 'nullable|string',
        'email' => 'nullable|email',
        'idade' => 'nullable|integer|min:0'
    ]);

    if ($validator->fails()) {
        return response()->json(['erros' => $validator->errors()], 422);
    }

    $usuario->update($request->only(['nome', 'email', 'idade']));

    return response()->json(['mensagem' => 'Usuário atualizado com sucesso', 'usuario' => $usuario]);
}

✅ Passo 7: Criar o AuthController

bash

📁 app/Http/Controllers/AuthController.php:

php
namespace App\Http\Controllers;

use App\Models\Usuario;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

class AuthController extends Controller
{
    public function registro(Request $request)
    {
        $request->validate([
            'nome' => 'required|string',
            'email' => 'required|email|unique:usuarios',
            'idade' => 'required|integer|min:0',
            'senha' => 'required|string|min:6'
        ]);

        $usuario = Usuario::create([
            'nome' => $request->nome,
            'email' => $request->email,
            'idade' => $request->idade,
            'senha' => Hash::make($request->senha),
        ]);

        $token = $usuario->createToken('token_api')->plainTextToken;

        return response()->json(['token' => $token, 'usuario' => $usuario], 201);
    }

    public function login(Request $request)
    {
        $usuario = Usuario::where('email', $request->email)->first();

        if (!$usuario || !Hash::check($request->senha, $usuario->senha)) {
            throw ValidationException::withMessages([
                'email' => ['Credenciais inválidas.'],
            ]);
        }

        $token = $usuario->createToken('token_api')->plainTextToken;

        return response()->json(['token' => $token]);
    }

    public function logout(Request $request)
    {
        $request->user()->currentAccessToken()->delete();

        return response()->json(['mensagem' => 'Logout realizado com sucesso.']);
    }
}

Relações no MongoDB: Joins e Aninhamentos

1. MongoDB é um banco NoSQL orientado a documentos

  • Ele armazena dados em documentos JSON-like (BSON).

  • Diferente do SQL, não tem tabelas, mas collections.

2. Relações entre documentos podem ser feitas de duas formas principais:

🟢 A. Dados Aninhados (Embeded Documents)

Você guarda documentos relacionados dentro do documento principal, como um campo que contém um array ou subdocumento.

Exemplo:

json
{
  "_id": 1,
  "nome": "João",
  "enderecos": [
    {
      "rua": "Rua A",
      "cidade": "São Paulo"
    },
    {
      "rua": "Rua B",
      "cidade": "Rio de Janeiro"
    }
  ]
}

  • Vantagem:

    • Consulta única, sem precisar de joins.

    • Rápido para acessar tudo junto.

  • Desvantagem:

    • Pode aumentar muito o tamanho do documento.

    • Difícil atualizar partes aninhadas isoladamente.

🟠 B. Referências entre Collections (Similar a Joins)

Você armazena o _id (ou outra chave) de outro documento para "referenciar" dados em outra collection.

Exemplo:

Usuários:

json
{
  "_id": "abc123",
  "nome": "João"
}

Pedidos:

json
{
  "_id": "pedido1",
  "usuario_id": "abc123",
  "total": 150
}

Como fazer "join" entre collections no MongoDB?

MongoDB tem o $lookup, que funciona como um JOIN.

Exemplo prático $lookup

Imagine que você quer listar pedidos com dados do usuário.

js
db.pedidos.aggregate([
  {
    $lookup: {
      from: "usuarios",          // collection para juntar
      localField: "usuario_id",  // campo em pedidos
      foreignField: "_id",       // campo em usuarios
      as: "dados_usuario"        // nome do campo resultado
    }
  }
])

No Laravel usando o driver MongoDB

  • O pacote oficial Laravel Eloquent não tem join nativo para MongoDB.

  • Você pode usar o Aggregation Framework com $lookup diretamente no MongoDB:

Exemplo com MongoDB query builder em Laravel:

php
$pedidos = DB::collection('pedidos')->raw(function($collection) {
    return $collection->aggregate([
        [
            '$lookup' => [
                'from' => 'usuarios',
                'localField' => 'usuario_id',
                'foreignField' => '_id',
                'as' => 'dados_usuario'
            ]
        ]
    ]);
});

Recomendações

Quando usar:Qual abordagem escolher?
Dados pequenos, fortemente ligadosEmbed (aninhamento)
Dados grandes, muitos relacionamentosReferência + $lookup
Quando precisa de performance simples e rápidaEmbed
Quando precisa flexibilidade e escalabilidadeReferência + joins via $lookup

        return $collection->aggregate([
            [
